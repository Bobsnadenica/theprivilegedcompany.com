    02 / Names without the mystery

    What does each part do?

    Identity

    IdP & application session

    The identity provider checks who you are. The application session lets the app act as that user. Permission to open an app does not prove that a phone is connected.

    Network edge

    Carrier & SBC

    The carrier connects to the public telephone network (PSTN). A Session Border Controller manages signaling and often media at a voice network boundary. Exact hops depend on the deployment.

    SBC functions

    Caller interaction

    VRU / IVR

    VRU means Voice Response Unit. IVR means Interactive Voice Response: menus such as “Press 1 for support.” Think prompts, collected digits and the next routing decision.

    RingCentral confirms the VRU term · VRU function

    Routing

    Queue / ACD

    A queue holds waiting callers. Automatic Call Distribution selects eligible agents using configured rules. Signed in, assigned to a queue and available are separate conditions.

    RingCX queues

    Call control

    SIP & SDP

    SIP sets up, changes and ends a call. SDP describes proposed media, including codecs and addresses. SIP success is not proof that audio flows in both directions.

    SIP standard · SDP standard

    Audio

    RTP / SRTP & RTCP

    RTP carries real-time media; SRTP protects it. RTCP provides control and reception reports. A headset problem and a blocked media path can both sound like silence.

    RTP / RTCP · SRTP

    A few more useful terms

    Call leg: one segment of a call, such as customer-to-platform or platform-to-agent. A transfer can introduce another leg.

    WebRTC: technology for real-time voice and video in browsers. DTMF: the signals produced by keypad digits. DND: Do Not Disturb.

    MOS: Mean Opinion Score, used as a voice-quality indicator. Jitter: variation in packet arrival timing. Packet loss: expected packets that do not arrive at the receiver.

    Terminology checkpoint

    EIQ, EID and ECC: verify the local meaning.

    EIQ and EID: the public sources reviewed do not establish these as named RingCentral voice components. Their expansions, roles and positions in a call path remain unverified.

    ECC: RingCentral’s Contact Center release notes use it for Enhanced Customer Card, which displays customer context. That does not establish the meaning of an ECC service in your environment. Documented ECC usage.

    To map a local label, obtain its approved service definition, owning team, product/version and a sanitized trace showing upstream and downstream calls. Until then, use the functional names above. Do not assign a failure to a component from its acronym alone.

    03 / Read the conversation

    Ringing is not the same as audio.

    A simplified successful SIP call leg looks like this. Proxies, authentication, early media and additional legs are omitted.

    Caller sideSignaling on one call legCalled side
    INVITE · start a call
    180 Ringing · alerting
    200 OK · INVITE accepted
    ACK · acknowledge
    RTP / SRTP · audio in both directions
    BYE · end this call
    200 OK · BYE accepted

    A 200 OK for an IVR leg can mean the platform answered before an agent joined. Match each response to its request and leg. SIP messages and responses.

    Response codes: clues, not root causes
    SIP responseInterpretationNext check
    401 / 407An authentication challenge can be normal.Check whether an authenticated retry succeeds. Repeated challenges need investigation.
    403 ForbiddenThe server refuses the request.Inspect the emitting hop, account policy, caller identity and response details.
    404 Not FoundThe requested user or domain was not found there.Check the Request-URI, number normalization and routing destination.
    408 / 480Request timeout / temporarily unavailable.Check downstream responses, endpoint reachability and timing. These codes have different meanings.
    486 Busy HereThe reached endpoint is busy.Check endpoint state and alternate routing. Busy is not necessarily a platform outage.
    487 Request TerminatedThe request was terminated.Look for a preceding CANCEL and who sent it; a caller may have hung up.
    488 Not Acceptable HereThe session offer is unacceptable at this endpoint.Compare SDP, supported codecs and media/security requirements.
    503 Service UnavailableThe server is temporarily unable to process the request.Check the origin, Retry-After if present, capacity and alternate routes.

    HTTP 401/403 in a login API and SIP 401/403 in a call trace belong to different protocols. Read the method, response body and surrounding events.

    04 / Find the failing boundary

    Start with a symptom.

    These are investigation paths, not automatic diagnoses. Select a symptom to see where to begin and what evidence to collect.

    Inspect in Kibana

    Inspect in SIP3 Hoof

    Before naming a cause

    Kibana: application evidence

    Use Discover to inspect ingested application, identity and routing events. Choose the correct data view and an absolute time window. Sort by time and follow the request or interaction identifier.

    Start broad: search a known, sanitized identifier across indexed fields.

    "demo-interaction-001"

    Then narrow: this example requires these fields to exist in your data.

    trace.id: "demo-trace-001" AND
http.response.status_code >= 400

    Use KQL mode. Field names and identifiers are examples, not a RingCentral log schema. An empty result does not prove no request occurred. Check ingestion, retention and access.

    KQL syntax · Discover

    SIP3 Hoof: signaling evidence

    Hoof is SIP3’s web interface. Set the same time window, search a call and inspect its legs, messages and available media reports.

    Find one SIP leg:

    sip.call_id=demo-call-001

    Find failed calls:

    sip.state=failed

    Find flagged one-way streams:

    rtp.one_way=true

    These are separate SIP3 Advanced Search examples, not KQL. Results depend on capture coverage, installed version and media collection. A one-way flag is a clue, not proof of the root cause.

    Search attributes · Call Flow and Call Details

    Correlate; do not equate. An application interaction ID, an agent login ID and a SIP Call-ID are different identifiers. One interaction can contain several SIP legs. Use logged mappings, timestamps and endpoints to join the evidence. SIP3 can only show traffic or reports supplied to it; encrypted or uncaptured traffic can leave gaps.
    Worked example: agent sees the caller, but cannot hear
    1. Record the direction of missing audio: the agent cannot hear the caller. Confirm the caller can hear the agent.
    2. In Hoof, check successful setup on both relevant legs. Do not stop at the IVR’s answer.
    3. Inspect caller-to-agent media reports and negotiated SDP addresses. Compare with the working agent-to-caller direction.
    4. In Kibana, match the interaction and agent session. Look for media setup errors or a connection change at the same time.
    5. Check the agent’s selected speaker, volume and headset. If media disappears between two observed points, investigate that network segment. If media reaches the endpoint, investigate playback.
    6. Report the evidence and remaining gap. “One-way audio” alone does not prove a firewall fault.
    Minimum evidence for a useful escalation
    • Product, tenant/account, region, affected agent or extension, app version and scope: one user, one site or many.
    • Exact timestamp with timezone, direction, expected behavior and actual behavior.
    • Interaction ID, agent/session ID and all relevant SIP Call-IDs, with the mapping between them.
    • Last successful step, first failed step, emitting host and exact protocol response.
    • A comparable successful example, affected route, recent changes and known collection gaps.

    Share only necessary, approved evidence. Redact credentials, tokens, private numbers and customer content before exporting logs or captures.
