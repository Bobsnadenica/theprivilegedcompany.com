Two jobs, one platform. RingEX provides employee business phones. RingCX / Engage Voice handles contact-center agents, queues and dialing. The examples show functional steps; the exact setup depends on your product.

Start here / The missing connection

Offhook: the agent’s line is connected.

Originally, “off hook” meant lifting a telephone handset. In a persistent RingCX / Engage Voice session, it means keeping the agent’s voice connection to the platform open between customer calls.

Offhook does not mean “talking to a customer.” An agent can be connected but unavailable, or connected and waiting.

The agent connects to the platform. With a phone destination, the agent answers that connection. No customer has joined.

Illustrative persistent connection. In per-call mode, the agent’s phone can connect for each call instead. A disconnected line is not automatically a fault. Follow the configured mode.

Login, registration, offhook, available: what is the difference?
  • Login: you can use the application.
  • Registration: a SIP phone tells the voice service where it can be reached. This is not a conversation.
  • Offhook: the agent’s phone line is connected. In persistent mode, this is the standing agent leg.
  • Available: the routing system may offer calls if the agent also has the right queue access.
  • Wrap-up: after-call work, such as saving notes or selecting a result, before taking the next call.
What should I check in RingCX agent status?

Where your reporting integration exposes these fields, read them together:

  • agentLoginId: which agent session you are examining.
  • isOffhook: whether the agent line is offhook.
  • agentState: whether the agent is available, on a call or in another state.
  • callUii: the active customer interaction, when present.
  • lastUpdate: when that record last changed. Also check that your collection is current.

An offhook flag alone proves neither an active customer call nor good audio. Your Kibana field names may differ from the API fields.

    What can go wrong?

    First check

    Does every RingCentral call follow this exact route?

    No. An employee call may go straight to an extension. Contact-center calls can use menus and queues. Automated outbound campaigns dial differently from the manual example here. Legacy Contact Center / MAX has its own agent-leg setup.

    Know the parts

    What does each part do?

    Separate the app, the call instructions and the audio. One can work while another fails.

    Access

    Identity & app session

    Checks who you are and lets you open the app. Investigate here when sign-in fails.

    Call setup

    Session controller

    Registers phone endpoints and coordinates sessions. A phone can be registered without being on a call.

    Outside calls

    Carrier & SBC

    The carrier reaches external telephone networks. An SBC manages the boundary between voice networks. Check where a call is accepted or rejected.

    Menus

    VRU / IVR

    Voice Response Unit / Interactive Voice Response. Plays “Press 1 for support,” collects input and selects the next step.

    Agent selection

    Queue / ACD

    The queue holds callers. Automatic Call Distribution chooses an eligible agent using availability, queue access and routing rules.

    Connected audio

    Media server / bridge

    Connects the audio between call legs. The agent leg and customer leg are separate connections, not one login session.

    SIP, SDP, RTP and other terms you will see
    • SIP: instructions to start, change or end a call.
    • SDP: the proposed audio settings, including addresses and codecs.
    • RTP / SRTP: audio packets; SRTP protects them. RTCP carries reception reports.
    • WebRTC: technology for browser calls. DTMF carries keypad digits.
    • ANI / DNIS: the calling number / dialed number in telephony records. Compare these with the actual call.
    • RNA: Ring No Answer. A call was offered but was not answered.
    • MOS: a voice-quality score. Jitter is uneven packet timing; packet loss means packets did not arrive.
    What about EIQ, EID and ECC?

    These labels need your team’s service definitions. EIQ and EID are not verified here. ECC has different meanings across products. Do not guess that a label means “login server” or “call controller.” Confirm its role and owner in the service map before investigating it.

    Your first investigation

    Find the first broken step.

    1. Pin down one example. Record the time, timezone, direction, agent and affected number.
    2. Check the scope. One agent, one queue, one office or many customers?
    3. Join the evidence. Use the interaction and session IDs to find the related SIP call legs.

    Kibana: check the application

    SIP3 Hoof: check the call

    Do not jump to this conclusion

    Kibana: what did the app do?

    Open Discover. Choose the correct data and an absolute time window. Search a known interaction ID, then follow the events in time order.

    "demo-interaction-001"

    This KQL example searches indexed fields. Replace the example ID. Your logs must contain it.

    Look for: login result, agent session, offhook request, state change, queue offer and application errors.

    SIP3 Hoof: what happened to the call?

    Hoof is SIP3’s web interface. Use the same time window. Open the matching leg and inspect the call flow and available media reports.

    sip.call_id=demo-call-001

    This is SIP3 syntax, not KQL. Use a real SIP Call-ID. An offhook leg may start well before the customer call.

    Look for: who sent the request, who answered, who rejected it and which audio direction fails.

    Different IDs, related events. A user ID, agent login ID, interaction ID and SIP Call-ID are not interchangeable. One customer interaction can have several call legs. No search result can also mean missing capture, wrong time range or expired retention.
    Example: offhook connects, but no customer calls arrive
    1. Confirm the agent line is connected. A successful offhook attempt only proves that connection.
    2. Check the agent state. “Unavailable” or unfinished wrap-up can explain why there is no offer.
    3. Check the target queue: active, correct schedule, waiting calls and agent access.
    4. Find an offer in Kibana. No offer points toward routing or state; a failed offer points toward call delivery.
    5. If delivery failed, inspect the agent leg in Hoof. Report the exact response and sender.
    Example: the customer hangs up, but offhook stays connected

    This can be normal in persistent mode. The customer leg ends; the agent leg stays open for the next call. Check wrap-up and availability rather than treating the remaining agent connection as a stuck customer call.

    Example: the agent cannot hear the customer
    1. Confirm whether the customer can hear the agent. Name the missing direction.
    2. Check the headset, selected speaker, volume and mute settings.
    3. In Hoof, inspect both call legs and the customer-to-agent media path. An answered call does not prove audio works.
    4. Match the session in Kibana and check connection or device changes.
    5. Report where media stops being observed. Silence alone does not prove a firewall fault.
    What to include when escalating

    Product and account, affected users/sites, exact time with timezone, expected and actual behavior, relevant IDs, last working step, first failure, exact response and sender. Include a successful comparison if possible. Redact tokens, private numbers and customer content.
